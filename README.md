# AI Recruiter

AI Recruiter 是一个基于 `boss-cli` 的本地招聘工作台。最终版本保留只读优先的 BOSS 集成，把同步数据、候选人标注、匹配建议、沟通时间线、简历文件和 Agent 任务放进本地可追踪的数据库。

## 能力范围

- 只读读取 BOSS 岗位和已建立沟通的候选人；
- 手动同步到 SQLite，使用远端 ID 或稳定组合键去重，保留同步记录和原始快照；
- 候选人阶段、负责人、收藏、跟进时间、标签、备注和阶段历史；
- 本地搜索、岗位/阶段/标签筛选、时间线和漏斗统计；
- 不依赖外部 API key 的确定性匹配基线，输出分数、证据、优势、风险和待确认问题；
- 简历 TXT、MD、PDF、DOCX 文件的本地归档、哈希去重、文本提取和结构化摘要；
- 消息和 BOSS action 草稿、显式确认、幂等键、审计记录、紧急停止开关；
- Agent 的同步、批量匹配和每日建议任务。Agent 不绕过人工确认执行 BOSS 写入。
- AI 管理：连接 OpenAI 兼容 API，保存提示词，手动选择本地候选人及简历截图进行分析，保留任务进度和结果。

默认 `BOSS_ENABLE_WRITES=false`，用于限制原有 Action/Agent 写入；即使创建了这些动作的草稿，确认后也只会记录为 blocked。推荐牛人的手动批量打招呼采用独立的单次授权：用户勾选明确人选、核对岗位并确认整批名单后，仅为这批人执行，不会打开全局写入开关。所有打招呼仍受紧急停止开关约束。

## 环境和启动

Windows 首次部署见 [环境依赖与部署清单](DEPLOY_WINDOWS.md)。下载项目后双击 `install-ai-hr.bat`，可检查并安装缺少的 Python 3.11+、Node.js 20+ 和 Google Chrome，再创建根目录 `.venv`、安装项目依赖并构建。`boss-cli/` 已包含在本仓库，不需要子模块。

```powershell
git clone https://github.com/Jack1445/AI_HR.git
Set-Location AI_HR
.\install-ai-hr.bat
.\start-ai-hr.bat
```

以下为手动开发启动方式。

PowerShell：

```powershell
Copy-Item .env.example .env
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e "backend[dev]"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload --port 8000
```

Git Bash：

```bash
cp .env.example .env
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -e 'backend[dev]'
./.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --reload --port 8000
```

另开一个终端启动前端：

```powershell
Set-Location frontend
npm install
npm run dev
```

打开 <http://localhost:5173>；健康检查为 <http://localhost:8000/api/health>。后端从项目根目录启动，默认才能正确找到 `boss-cli/dist/cli/index.js`。手动部署时，先在 `boss-cli/` 中执行 `npm ci`、`npm run build`。首次使用 BOSS 时，在工具打开的 Chrome 窗口内人工登录。

### 一键启动（PowerShell）

以后可以直接在项目根目录运行：

```powershell
.\start-ai-hr.ps1
```

脚本会自动创建 `.env`（如果不存在），先清理 8000 和 5173 端口上的旧服务，再启动前后端，等待服务就绪，并优先使用已安装的 Google Chrome 打开 `http://localhost:5173`。也可以双击项目根目录中的 `start-ai-hr.bat` 启动。后端和前端窗口需要保持运行；停止服务时关闭这两个窗口即可。

网页使用的 Chrome 只是打开 AI Recruiter 界面；BOSS 数据读取仍由 `boss-cli` 的 CDP Chrome 会话完成。该会话的 Cookie 保存在 `~/.boss-cli/.cache/browser-data`，首次同步时如果该会话尚未登录，需要在它打开的 Chrome 窗口中完成一次 BOSS 登录。

网页“岗位”卡片中的“诊断同步”会沿用同一套只读同步流程，并把每个阶段的时间、进程号、工作目录、CLI 参数、退出码、耗时、标准输出和错误输出写入项目根目录的 `data/diagnostics/sync-*.log`。诊断失败时，页面错误提示会直接给出日志路径；日志只保存在本机，不包含浏览器 Cookie 或登录凭证。

### 分段耗时诊断（后端 v0.2.4）

重启 `start-ai-hr.bat`，确认网页后端版本为 `0.2.4`，再点击“诊断同步”。同步期间，“调试信息”每两秒刷新各步骤的状态和耗时；日志实时写入，不必等整个 CLI 退出后才能定位等待位置。

网页打开、刷新和选择岗位只读取本地快照；点击“同步”或“诊断同步”才读取 BOSS 最新数据。首次使用没有本地数据时，页面提示先同步，避免网页的自动岗位读取占用浏览器，让手动同步长时间排队。

直接调用只读 API 的 CLI 请求也会生成 `data/diagnostics/cli-*.log`。排队日志会记录当时占用执行锁的命令 ID 和日志路径；调试信息显示当前执行命令，便于追查多个窗口或外部请求造成的竞争。共享浏览器仍按顺序操作。

- 普通同步也保存轻量计时日志，仅记录步骤、时间、进程和数据量；诊断同步额外保存完整 CLI 输出，日志可能包含候选人资料，应只留在本机。
- 记录后端队列等待、CLI 启动、首次数据输出、软件更新检查、会话锁、连接浏览器、页面初始化、导航、固定等待、列表就绪、文字提取、输出解析、数据库保存、断开连接以及清理后等待进程退出的耗时。
- `cli.update_check` 是 boss-cli 自身的 npm 版本检查，不是 BOSS 数据读取，也不自动安装更新。
- 每条日志顶层 `elapsed_seconds` 表示距本次同步开始的时间；`details.elapsed_seconds` 表示该步骤的耗时。`command_id` 关联同一个 CLI 调用，`span_id` 关联同一个步骤的开始与结束。
- 网页耗时表可点击耗时列排序。父步骤包含子步骤，不能将各行简单相加；以 `sync.total` 为整个同步耗时。超时会保留部分输出和最后一个未完成步骤。

这些埋点仅用于测量，不改变上游等待时间、更新检查或页面导航行为。再次构建 `boss-cli` 时应保留本地计时补丁。

2026-10-21 已修复 boss-cli 首次启动 Chrome 后遗留 stdout/stderr 管道，导致 CLI 读完岗位仍不退出、后续请求排队直到 120 秒超时的问题。修复前后证据及独立浏览器回归测试见 [同步排队与 CLI 退出故障](docs/diagnostic-run-20261021.md)。

如果 PowerShell 中 `python` 不可用，请使用已创建环境的绝对路径；如果在 Git Bash 中启动，必须使用 `./.venv/Scripts/python.exe` 这种斜杠写法。

## 主要接口

### 推荐牛人手动打招呼（v0.4.1）

- 勾选记录后，选择工具栏会出现“一键打招呼”。确认窗口列出完整岗位、姓名、基本信息；确认后才发送，最多 200 人一批，逐人串行执行。
- `POST /api/recommendation-greetings` 接收本地人选 ID、岗位 ID、确认标记与唯一请求 ID；服务器从本地数据库获取身份。`GET` 返回最近任务及逐人结果。后台任务与同步/截图共用浏览器操作锁，刷新或切换页面不会重发。
- CLI `recommend-greet` 精确选择岗位，并在点击的同一次 DOM 执行中校验 BOSS ID、姓名、基本信息（忽略活动状态词），不使用姓名模糊匹配。当前列表找不到的人会显示“未找到”，不会自动刷新或搜索其他人。
- 点击前持久记录执行占位；已招呼、已发送及结果不明的人不会自动重发。超时、服务中断、验证码、额度或付费弹窗会停止后续执行，结果保留供人工核实。不自动购买额度或确认平台弹窗。
- 本地删除推荐人选后，招呼防重记录仍保留岗位与 BOSS ID 的不可逆组合哈希及结果，避免再次入库造成重复发送。任务明细保存已确认的名单和逐人结果用于核对。
- 此功能直接使用 BOSS 的默认打招呼行为，不调用 AI，也不发送自定义聊天内容。
- 推荐表格的“已打招呼”列按当前岗位显示本平台的成功发送记录：成功为绿色“是”，默认为灰色“否”，逐人完成后自动更新，刷新后保留；已有成功记录也会显示。失败、结果待核实及仅在 BOSS 发现此前已招呼的记录不会误标为本平台发送成功。该列支持筛选、排序和显隐。

### AI 管理（v0.4.4）

工作台新增第三个页面 **AI 管理**，使用流程：

1. 填写服务商的 API 基础地址和 API Key，点击“保存并获取模型列表”。后端使用已保存密钥请求 `GET {Base URL}/models`，从可搜索下拉框选择模型，选择会自动保存。再次打开 AI 页面时自动获取列表并保留已有选择；列表缺失或不支持时可手动填写模型 ID。只填域名自动补 `/v1`，已含 `/v1` 或其他路径时保留；也兼容粘贴完整的 `/chat/completions`、`/models` 地址。支持本机 HTTP 免密模型，远程服务须使用 HTTPS。
2. 可配置温度（默认不传）、输出 Token 上限、Token 参数名和超时。点击“保存并测试连接”，只发送测试文字；此操作会产生少量 API 用量。模型是否支持图片需以实际分析确认。
3. 编写提示词，按“推荐牛人 / 沟通候选人”和岗位筛选本地记录，明确勾选要分析的人选（每次最多 20 人）。可补充岗位 JD，并预览实际文字资料及图片；预览不调用模型。
4. 推荐牛人的“附带在线简历截图”默认关闭；开启后将本地 PNG 作为图片输入发送给支持图片的模型。未保存图片的人选仅发送文字，并在资料里明确标注。沟通候选人读取本地最近消息、备注、标签和已提取的简历文字，并非抓取 BOSS 全部历史消息。
5. 点击“保存并开始分析”，逐人调用模型；每人都收到保存的提示词和其资料快照。分析结果单独保存，不自动修改契合程度、招聘阶段或发送打招呼。切换页面仍显示任务提示，刷新后在 AI 管理中可恢复查看；服务重启会标记未完成任务，不自动再次付费调用。

密钥使用当前 Windows 用户的 DPAPI 加密，数据库和接口响应不保存/返回明文密钥；更换 API 地址需重新填写或清除密钥。密钥目前仅支持 Windows 加密保存，迁移到其他电脑/用户后需重填。模型请求从后端发出，候选人资料只在手动运行时发往配置的服务商。任务、提示词、资料快照与结果都在忽略上传的本地 SQLite 中。

接入 New API 时，填写实际部署/服务商提供的地址，例如 `https://你的服务域名/v1`，以及该平台生成的 API 密钥（令牌），文档网站本身不是 API 地址。其 `GET /v1/models` 默认返回 OpenAI 格式，匹配本应用的 `data[].id` 解析方式；获取模型目录不发送候选人资料、不调用推理。列表不代表每个模型都支持聊天或图片，需要按平台能力选择。当前分析协议为 OpenAI 兼容的 `POST /chat/completions`，不直接发送 Anthropic 原生 Messages 或 Gemini 原生请求。参考 [New API 接入说明](https://docs.newapi.pro/zh/docs/guide/feature-guide/user/api) 和 [OpenAI 模型列表文档](https://developers.openai.com/api/reference/resources/models/methods/list)。

接口：`GET/PUT /api/ai/config`、`POST /api/ai/models`、`POST /api/ai/test`、`GET /api/ai/data`、`POST /api/ai/preview`、`POST/GET /api/ai/runs`、`GET /api/ai/runs/{id}`。

如服务商返回 `MissingSessionID`，可在高级参数中开启“发送会话标识”。开启后，每次独立的单人分析或连接测试会携带随机 `x-opencode-session`；标识不包含候选人或密钥信息，客户端使用真实的 `AI-HR` User-Agent。默认关闭，更换 Base URL 时关闭此选项。此设置来自部分上游线路的要求，参考 [OpenCode 会话标识说明](https://opencode.ai/v2/docs/console/go/#where-can-i-use-it)。平台报错会明确提示缺少会话标识，不再误报为图片/Token 参数错误；失败后不自动重试付费请求。

请求中的文字/图片消息格式、温度及 Token 参数参考 [OpenAI Chat Completions 官方文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。不同服务商及模型对参数的支持可能不同，需按其文档填写。现有候选人详情中的规则匹配入口保持独立，不会暗中调用付费模型。

### 沟通分类与推荐牛人（v0.2.5）

#### 按岗位推荐（v0.3.1，当前单次上限 20 人）

- 推荐牛人上方新增岗位选择器。“刷新 BOSS 岗位”只读取 BOSS 推荐页的岗位下拉选项；打开页面和切换岗位只查询本地缓存，不抓取候选人。
- “新增 20 人（含简历）”针对所选岗位运行，先用完整岗位标签精确切换并核对，再读取最多 20 位新人，逐人截图。候选人不足或达到有界查找上限时返回实际人数。行内补截图也核对来源岗位。
- 名单、查重和新删除记录按岗位隔离。同一岗位仍使用姓名＋基本信息联合查重；同一人出现在两个岗位时是两条独立本地记录，各自保留自定义值。删除当前岗位的记录不删除其他岗位的记录或其截图。
- 历史记录按已有 `source_job` 归属，缺少来源的记录单列为“历史未归属岗位”，不能直接读取。旧版无岗位信息的回收站排除项保持全局生效，界面标明“历史全局排除”。取消这类排除会对所有岗位生效。
- 岗位使用完整显示标签区分（含城市、薪资）；同名不同标签不合并，完整标签重复时报错。若 BOSS 修改标签，会保留旧标签下的历史名单，不凭相似名称猜测合并。
- 新增迁移 `20261026_0007`。更新后需要重新构建 boss-cli、重启 v0.3.1 后端；先刷新 BOSS 岗位，再选择岗位并手动新增。离线验证新增 `backend/tests/test_recommendation_jobs.py` 与 `boss-cli/scripts/test-recommendation-jobs.mjs`。

#### 字段与表格管理（v0.3.0）

- 沟通候选人与推荐牛人共用表格管理工具栏：字段显隐、显示名称、拖动列顺序、拖动列宽、左右固定列、搜索、且/或组合筛选、多字段排序、分组折叠、视图新增/复制/重命名/删除。
- 自定义字段支持文本、多行文本、数字、日期、单选、多选、复选框。点击单元格填写，勾选多行后可以批量填写或删除。删除字段会先显示已填写的记录数；系统来源字段不能被改写或删除。已有字段的类型和已使用的选项不直接转换，以避免损坏历史值。
- 字段定义、视图配置、手动行顺序和自定义值均存入 SQLite。视图设置自动保存，配置版本冲突会提示重新加载。行拖动/置顶/置底只在无字段排序、无分组时启用；筛选不会清理不可见记录的顺序。
- 推荐牛人新增“检索日期”：按北京时间显示第一次成功获取在线简历截图的日期，后续重新截图不覆盖该日期；旧数据按可归属的历史截图时间补齐，未截图显示“未读取”。沟通候选人显示“首次同步日期”。
- 本地备注为独立的可编辑字段；沟通候选人的招聘阶段、标签、负责人可在表格中编辑。后续同步保留本地标注。来源岗位、负责人及本地备注等较少使用的列默认隐藏，可在“字段”中打开。
- 推荐回收站继续只保存姓名＋基本信息。沟通候选人新增回收站：删除会清理该候选人的全部本地岗位关联、资料、附件文件和字段值，用现有同步来源键（当前为姓名＋来源岗位）阻止重新同步。允许重新同步后，只在下次手动同步时重新入库，已删除的本地资料不恢复。不会对 BOSS 执行删除、发送或打招呼。
- 新增迁移 `20261026_0006`（开发启动自动创建新增表）。重启 `start-ai-hr.bat` 加载 v0.3.0；不需要重新构建 boss-cli。既有手动新增最多 10 人、联合查重和手动补截图机制保持不变。
- 验证：`pytest backend/tests -q`、前端 `npm run build`、`node frontend/scripts/test-table-model.mjs`、`node frontend/scripts/test-recommendation-batch.mjs`。表格测试使用模拟数据，不调用 BOSS。

#### 推荐人才库与在线简历截图（v0.2.9）

- 推荐名单持续积累。点击“新增10人（含简历）”先按“姓名＋基本信息”联合查重（只规范化空白），两个字段都相同才跳过；同名但基本信息不同会分别保存。
- 每次只新增最多10人并依次截图，旧记录与截图保留。CLI 不足时向下滚动查找，最多15次滚动、连续3次无新卡片即停止，不足10人按实际人数保存，不会无限抓取。只有点击按钮才启动。
- 本地使用独立 `recommended_candidates` 表及联合字段哈希唯一约束。首次访问自动迁入旧快照和关联截图，保留原始快照；无法恢复此前已被覆盖且未保存的历史名单。

- `GET /api/local/recommendations/recycle-bin` 只返回回收站的内部编号、姓名和基本信息。已删除人选与现有名单共同组成 CLI 查重列表，后端入库时再次拦截相同双字段。
- `POST /api/local/recommendations/recycle-bin/{identity_key}/restore` 解除这一条回收站排除记录。仅操作本地数据库，沿用手动读取互斥锁；同名但基本信息不同的其他排除记录保持不变。
- 行内“读取在线简历”“重新读取”保留供单独重试，失败保留旧图。批量只处理本次 `added_ids`，不重复打开已有人员简历；请保持网页打开直到完成。

## 数据和安全边界

开发数据库由 Alembic revision `20261018_0001` 创建，应用启动时也会安全地补齐本地开发表。运行数据、简历文件、Cookie、联系方式和 `.env` 都被 `.gitignore` 排除。常规应用日志只记录命令错误摘要和审计元数据；诊断同步日志会保存 CLI 的完整标准输出和错误输出，便于定位页面或登录问题，但不读取或写入浏览器 Cookie、密码等登录凭证。

`boss-cli` 源码直接保存在本仓库，保留其 GPL-3.0 许可证；AI Recruiter 通过子进程适配器调用它。BOSS 页面结构或登录状态变化时，需要检查 `boss-cli` 的浏览器操作并重新同步。

当前 Agent 任务在本地请求内串行执行，具备任务状态、失败重试和取消接口；生产部署前仍应在反向代理或应用层接入真实身份认证、角色权限和后台队列。`X-Actor` 只用于本地审计标识，不能替代生产认证。
